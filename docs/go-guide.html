Go od nuly saycut

Napíšeš vetu, dostaneš podpísaný Apple Shortcut. Postavíš to sám a po ceste pochopíš, prečo Go vyzerá presne tak, ako vyzerá.

prompt› Claude› cherri› sign› .shortcut
Ťukni na tlačidlo. Všimni si, čo sa stane, keď kompilácia zlyhá.

Čo staviame

MVP má 6 Go súborov, zhruba 300 riadkov a nula externých závislostí. Všetko robí štandardná knižnica Go. Všetky súbory sú v jednom balíku package main, takže ich Go vidí ako jeden program. Na balíky to rozdelíš až neskôr, keď ti bude main tesný.

saycut/
├── go.mod              meno modulu + verzia Go
├── main.go             vstup: argumenty → pipeline → výsledok
├── config.go           env premenné + validácia
├── llm.go              HTTP volanie Claude API
├── cherri.go           spustí kompilátor cherri
├── sign.go             spustí shortcuts sign
├── pipeline.go         retry slučka, lepidlo všetkého
├── pipeline_test.go    prvý test
├── prompts/system.md   ako má Claude písať Cherri
├── examples/hello.cherri  ručne overený príklad
└── Makefile

Štart projektu:

mkdir saycut && cd saycut
go mod init github.com/moudlajs/saycut
go run .          # spustí balík v aktuálnom priečinku
Najprv fáza 0. Ručne skompiluj a podpíš hello.cherri a over si presné flagy cherri a shortcuts sign. Kód nižšie predpokladá, že cherri vyrobí meno.shortcut vedľa zdrojáku. Ak to robí inak alebo podpisuje sám, upravíš jeden riadok.
1

Prečo Go vyzerá divne

Tvoj pocit „C krížené s niečím“ je presný. Go navrhli v Google ľudia, ktorí robili Unix a C (Ken Thompson, Rob Pike). Z C prevzali zložené zátvorky a pointery a zvyšok vedome zjednodušili:

  • Typ je za menom: name string namiesto string name. Čítaš to zľava doprava: „name je string“. Pri zložitých typoch ako func(int) []string to zostane čitateľné.
  • Žiadne bodkočiarky. Dopĺňa ich kompilátor, preto { musí byť na rovnakom riadku ako if alebo func.
  • Jedna slučka: for. Žiadne while ani do.
  • Žiadne triedy, dedičnosť ani výnimky. Nie je to chýbajúca vec, je to zámer. Menej mágie znamená, že všetko vidíš priamo v kóde.
  • Formátovanie rieši gofmt, takže o medzerách sa nediskutuje.

Dekodér divných znakov

Ťukni na symbol. Tento zoznam pokrýva skoro všetko, čo ťa v Go zarazí.

2

Premenné a typy

var retries int              // zero value: 0
var name string              // zero value: ""
model := "claude-sonnet-5"   // typ string si Go odvodí

files := []string{"main.go", "llm.go"}   // slice = dynamický zoznam
files = append(files, "sign.go")         // append vracia NOVÝ slice

env := map[string]string{"SAYCUT_MODEL": "claude-sonnet-5"}
m, ok := env["SAYCUT_MODEL"]              // ok == false, ak kľúč chýba
Zero values. V Go neexistuje „undefined“. Každá premenná má od začiatku rozumnú hodnotu: 0, "", false alebo nil pri pointeroch, mapách a slicoch. Vďaka tomu nemusíš inicializovať všetko ručne.

Typy sú statické a Go nič nekonvertuje potichu. Z env premennej dostaneš vždy string a na číslo ju prevedieš explicitne cez strconv.Atoi, ktorý ti môže vrátiť chybu. Toto je pre Go typické: čo môže zlyhať, vidíš priamo v podpise funkcie.

Funkcie môžu vracať viac hodnôt. Na tom stojí celé spracovanie chýb:

n, err := strconv.Atoi("3")    // n == 3, err == nil
n, err = strconv.Atoi("tri")   // n == 0, err != nil
3

Structy namiesto tried

Struct je len vrecko s pomenovanými poľami. Nemá konštruktor, dedičnosť ani this. Správanie mu pridáš cez metódy a „konštruktor“ je obyčajná funkcia, ktorá sa podľa konvencie volá NewX alebo LoadX.

config.go

package main

import (
	"errors"
	"fmt"
	"os"
	"strconv"
)

type Config struct {
	APIKey     string
	Model      string
	MaxRetries int
	OutDir     string
}

func LoadConfig() (Config, error) {
	cfg := Config{
		APIKey:     os.Getenv("ANTHROPIC_API_KEY"),
		Model:      os.Getenv("SAYCUT_MODEL"),
		MaxRetries: 3,
		OutDir:     "dist",
	}
	if cfg.APIKey == "" {
		return Config{}, errors.New("ANTHROPIC_API_KEY is not set")
	}
	if cfg.Model == "" {
		return Config{}, errors.New("SAYCUT_MODEL is not set")
	}
	if v := os.Getenv("SAYCUT_MAX_RETRIES"); v != "" {
		n, err := strconv.Atoi(v)
		if err != nil {
			return Config{}, fmt.Errorf("SAYCUT_MAX_RETRIES must be a number: %w", err)
		}
		cfg.MaxRetries = n
	}
	return cfg, nil
}
  • Veľké písmeno znamená verejné. Config a APIKey vidí aj iný balík, apiKey nie. Namiesto public a private Go rozhoduje podľa veľkosti prvého písmena.
  • Config{APIKey: ...} je struct literál. Polia, ktoré nevyplníš, dostanú zero value.
  • if v := ...; v != "" je if s krátkou inicializáciou. Premenná v existuje len vnútri toho ifu.
  • Pri chybe vraciame Config{}, teda prázdny struct, a chybu. Volajúci sa pozrie najprv na chybu.

Metódu pridáš cez receiver, teda parameter pred menom funkcie:

func (c Config) Summary() string {
	return fmt.Sprintf("%s, %d pokusy", c.Model, c.MaxRetries)
}
// použitie: cfg.Summary()
4

Pointery: & a *

Keď v Go odovzdáš hodnotu funkcii, funkcia dostane kópiu, podobne ako fotokópiu papiera. Pointer je naopak link na Google Doc: kto ho má, upravuje originál.

  • &cfg znamená „daj mi link na cfg“, teda jeho adresu.
  • *Config v type znamená „link na Config“.
  • *p vo výraze znamená „otvor link“, teda hodnotu na adrese. Pri poliach structu to Go robí za teba, preto píšeš p.Model, nie (*p).Model.
func setModel(c Config)   { c.Model = "haiku" }  // zmení kópiu
func setModelP(c *Config) { c.Model = "haiku" }  // zmení originál

cfg := Config{Model: "sonnet"}
setModel(cfg)     // cfg.Model je stále "sonnet"
setModelP(&cfg)   // cfg.Model je teraz "haiku"
cfg (originál)Model: "sonnet"
⟵
c vo funkcii(funkcia nebeží)

Kedy použiť pointer: keď chceš meniť originál, keď je struct veľký, alebo keď ide o niečo zdieľané ako HTTP klient. Pre tvoje typy so stavom (*LLM, *Pipeline) používaj pointer receiver. Malé hodnotové veci ako Config pokojne kopíruj.

5

Chyby bez výnimiek

Go nemá try/catch. Chyba je obyčajná hodnota typu error, ktorú funkcia vráti ako poslednú. Uvidíš tento vzor stokrát:

out, err := doSomething()
if err != nil {
	return fmt.Errorf("do something: %w", err)
}

Každá vrstva pridá kontext a pošle chybu vyššie. %w („wrap“) pôvodnú chybu zabalí, nezahodí ju. Na konci dostaneš celý príbeh:

gave up after 3 attempts: cherri failed: exit status 1
line 4: unknown action "sendNotifcation"
Na prvý pohľad to vyzerá ako veľa opakovania. Výhoda je, že každé miesto, kde môže program zlyhať, vidíš priamo v kóde, bez neviditeľných skokov. Pre explicitný štýl, aký máš rád pri IaC, je to v podstate ideálne.

errors.Is(err, os.ErrNotExist) vie nájsť konkrétnu chybu aj v zabalenom reťazci. panic existuje, ale len pre situácie, keď je program úplne rozbitý. Bežné chyby ním nerieš.

Hovoríme s Claude

Nepotrebuješ SDK. Stačí HTTP POST s JSON telom a na tom si precvičíš structy, tagy aj pointery naraz.

llm.go

package main

import (
	"bytes"
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
	"time"
)

type Message struct {
	Role    string `json:"role"`
	Content string `json:"content"`
}

type apiRequest struct {
	Model     string    `json:"model"`
	MaxTokens int       `json:"max_tokens"`
	System    string    `json:"system"`
	Messages  []Message `json:"messages"`
}

type apiResponse struct {
	Content []struct {
		Type string `json:"type"`
		Text string `json:"text"`
	} `json:"content"`
}

type LLM struct {
	apiKey string
	model  string
	client *http.Client
}

func NewLLM(cfg Config) *LLM {
	return &LLM{
		apiKey: cfg.APIKey,
		model:  cfg.Model,
		client: &http.Client{Timeout: 90 * time.Second},
	}
}

func (l *LLM) Ask(ctx context.Context, system string, msgs []Message) (string, error) {
	body, err := json.Marshal(apiRequest{
		Model: l.model, MaxTokens: 4096, System: system, Messages: msgs,
	})
	if err != nil {
		return "", fmt.Errorf("encode request: %w", err)
	}

	req, err := http.NewRequestWithContext(ctx, http.MethodPost,
		"https://api.anthropic.com/v1/messages", bytes.NewReader(body))
	if err != nil {
		return "", fmt.Errorf("build request: %w", err)
	}
	req.Header.Set("x-api-key", l.apiKey)
	req.Header.Set("anthropic-version", "2023-06-01")
	req.Header.Set("content-type", "application/json")

	resp, err := l.client.Do(req)
	if err != nil {
		return "", fmt.Errorf("call API: %w", err)
	}
	defer resp.Body.Close()

	raw, err := io.ReadAll(resp.Body)
	if err != nil {
		return "", fmt.Errorf("read response: %w", err)
	}
	if resp.StatusCode != http.StatusOK {
		return "", fmt.Errorf("API returned %d: %s", resp.StatusCode, raw)
	}

	var out apiResponse
	if err := json.Unmarshal(raw, &out); err != nil {
		return "", fmt.Errorf("decode response: %w", err)
	}
	for _, c := range out.Content {
		if c.Type == "text" {
			return c.Text, nil
		}
	}
	return "", errors.New("API response has no text")
}
  • `json:"max_tokens"` je struct tag. Hovorí balíku encoding/json, ako sa pole volá v JSON. V Go je to MaxTokens, v API max_tokens.
  • apiRequest má malé písmeno, lebo mimo balíka ho nikto nepotrebuje. Polia má ale veľké, lebo json je iný balík a malé polia by nevidel.
  • Content []struct{...} je anonymný struct: tvar dát, ktorý potrebuješ len na jednom mieste a nemusíš ho pomenovať.
  • json.Unmarshal(raw, &out) dostane pointer, pretože má zapisovať do tvojej premennej. S kópiou by zapisoval do vzduchu. Tu vidíš zmysel kapitoly 4 v praxi.
  • defer resp.Body.Close() sa spustí pri odchode z funkcie, nech odíde ktorýmkoľvek return. Upratovanie tak máš napísané hneď vedľa otvorenia.
  • ctx (context) nesie timeout a zrušenie. Keď vyprší, request sa preruší. V Go ho podľa konvencie posielaš ako prvý parameter.
  • for _, c := range prechádza slice. _ zahadzuje index, ktorý nepotrebuješ.

Spúšťanie iných programov

Cherri aj shortcuts sú CLI nástroje. Go ich spustí cez os/exec, podobne ako keby si ich spustil v termináli.

cherri.go

package main

import (
	"context"
	"fmt"
	"os/exec"
	"strings"
)

// Compile returns the path of the compiled .shortcut.
// On failure the error contains cherri's output, so the LLM can fix its code.
func Compile(ctx context.Context, srcPath string) (string, error) {
	out, err := exec.CommandContext(ctx, "cherri", srcPath).CombinedOutput()
	if err != nil {
		return "", fmt.Errorf("cherri failed: %w\n%s", err, out)
	}
	// ASSUMPTION: foo.cherri -> foo.shortcut. Verify in phase 0.
	return strings.TrimSuffix(srcPath, ".cherri") + ".shortcut", nil
}

sign.go

package main

import (
	"context"
	"fmt"
	"os/exec"
)

func Sign(ctx context.Context, in, out string) error {
	cmd := exec.CommandContext(ctx, "shortcuts", "sign",
		"--mode", "anyone", "--input", in, "--output", out)
	if b, err := cmd.CombinedOutput(); err != nil {
		return fmt.Errorf("shortcuts sign failed: %w\n%s", err, b)
	}
	return nil
}
  • CombinedOutput() vráti stdout a stderr spolu ako []byte, teda surové bajty. %s ich vypíše ako text.
  • Výstup kompilátora vkladáme do chyby zámerne. Presne tento text pôjde späť do Claude ako „oprav toto“.
  • Argumenty sa odovzdávajú ako samostatné stringy, nie ako jeden príkaz pre shell, takže tu nehrozí shell injection.
Pozor: ak fáza 0 ukáže, že cherri na macOS podpisuje sám, sign.go zmažeš a pipeline je o krok kratšia.

Pipeline a retry slučka

Tu je jadro celej appky, presne to, čo si videl v simulácii hore. Keď kompilácia zlyhá, pridáme do konverzácie chybu a skúsime znova.

pipeline.go

package main

import (
	"context"
	"fmt"
	"log/slog"
	"os"
	"path/filepath"
	"strings"
)

type Pipeline struct {
	cfg    Config
	llm    *LLM
	system string
}

func (p *Pipeline) Run(ctx context.Context, name, prompt string) (string, error) {
	msgs := []Message{{Role: "user", Content: prompt}}
	var lastErr error

	for attempt := 1; attempt <= p.cfg.MaxRetries; attempt++ {
		slog.Info("generating", "name", name, "attempt", attempt)

		src, err := p.llm.Ask(ctx, p.system, msgs)
		if err != nil {
			return "", err // API is down: retrying compile won't help
		}
		src = stripFences(src)

		srcPath := filepath.Join(p.cfg.OutDir, name+".cherri")
		if err := os.WriteFile(srcPath, []byte(src), 0o644); err != nil {
			return "", fmt.Errorf("write source: %w", err)
		}

		unsigned, err := Compile(ctx, srcPath)
		if err != nil {
			lastErr = err
			slog.Warn("compile failed", "attempt", attempt, "err", err)
			msgs = append(msgs,
				Message{Role: "assistant", Content: src},
				Message{Role: "user", Content: "Compilation failed:\n" + err.Error() +
					"\nFix it. Reply with Cherri code only."},
			)
			continue
		}

		signed := filepath.Join(p.cfg.OutDir, name+".signed.shortcut")
		if err := Sign(ctx, unsigned, signed); err != nil {
			return "", err
		}
		slog.Info("done", "file", signed, "attempts", attempt)
		return signed, nil
	}
	return "", fmt.Errorf("gave up after %d attempts: %w", p.cfg.MaxRetries, lastErr)
}

// stripFences removes ```cherri ... ``` if the model wraps its answer.
func stripFences(s string) string {
	s = strings.TrimSpace(s)
	s = strings.TrimPrefix(s, "```cherri")
	s = strings.TrimPrefix(s, "```")
	s = strings.TrimSuffix(s, "```")
	return strings.TrimSpace(s)
}
  • for attempt := 1; attempt <= N; attempt++ je klasická trojdielna slučka, rovnaká ako v C.
  • []Message{{Role: ...}} je slice s jedným structom. Vnútorné {} sú struct a vonkajšie slice. Typ vo vnútri Go domyslí.
  • Konverzácia rastie cez append: Claude uvidí svoj pôvodný kód aj chybu, a preto ho vie cielene opraviť.
  • continue skočí na ďalší pokus. lastErr si pamätá poslednú chybu pre finálnu správu.
  • 0o644 je oktálové číslo, rovnaké práva ako pri chmod 644.
  • slog loguje štruktúrovane ako páry kľúč–hodnota. Neskôr ho prepneš na JSON výstup jedným riadkom.

main.go a prvé spustenie

main.go

package main

import (
	"context"
	"fmt"
	"log/slog"
	"os"
	"time"
)

func main() {
	if err := run(); err != nil {
		slog.Error("saycut failed", "err", err)
		os.Exit(1)
	}
}

func run() error {
	if len(os.Args) < 3 {
		return fmt.Errorf(`usage: saycut <name> "<what the shortcut should do>"`)
	}
	name, prompt := os.Args[1], os.Args[2]

	cfg, err := LoadConfig()
	if err != nil {
		return err
	}
	system, err := os.ReadFile("prompts/system.md")
	if err != nil {
		return fmt.Errorf("read system prompt: %w", err)
	}
	if err := os.MkdirAll(cfg.OutDir, 0o755); err != nil {
		return fmt.Errorf("create out dir: %w", err)
	}

	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Minute)
	defer cancel()

	p := &Pipeline{cfg: cfg, llm: NewLLM(cfg), system: string(system)}
	path, err := p.Run(ctx, name, prompt)
	if err != nil {
		return err
	}
	fmt.Println(path)
	return nil
}
Prečo main + run? os.Exit ukončí program okamžite a defer sa už nespustí. Preto celá logika beží v run(), ktorá vracia chybu, a main len rozhodne o exit kóde. Máš tak jedno miesto na exit a všetky defery prebehnú.

Interface a prvý test

Interface v Go je zoznam metód. Každý typ, ktorý tie metódy má, ho splňa automaticky, bez implements. Je to duck typing, ktorý overuje kompilátor.

type Generator interface {
	Ask(ctx context.Context, system string, msgs []Message) (string, error)
}

type Pipeline struct {
	cfg    Config
	llm    Generator   // namiesto *LLM
	system string
}

*LLM už metódu Ask má, takže nič iné meniť nemusíš. V testoch mu podstrčíš falošný generátor, ktorý nevolá API ani neminie žiadne tokeny. Rovnako neskôr spravíš Compiler interface a otestuješ celú retry logiku bez cherri.

Prvý test, v Go štýle „table-driven“:

pipeline_test.go

package main

import "testing"

func TestStripFences(t *testing.T) {
	tests := []struct {
		name, in, want string
	}{
		{"plain", "a", "a"},
		{"fenced", "```cherri\na\n```", "a"},
		{"spaces", "  a  ", "a"},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := stripFences(tt.in); got != tt.want {
				t.Errorf("got %q, want %q", got, tt.want)
			}
		})
	}
}

Súbor končiaci na _test.go sa kompiluje len pre go test. Tabuľka prípadov je slice anonymných structov: nový prípad pridáš jedným riadkom.

Čo ďalej: Telegram bot

Keď CLI funguje end-to-end, bot je len ďalší vstup do tej istej pipeline. Pribudne ti prvá externá závislosť (Telegram knižnica cez go get) a nový koncept, na ktorý je Go najviac známe:

for update := range updates {   // updates je channel
	go handle(update)          // každá správa vo vlastnej goroutine
}
  • Goroutine (go f()) je veľmi lacné paralelné vlákno. Kým jedna správa čaká 20 sekúnd na Claude, bot odpovedá ďalším.
  • Channel (chan, <-) je rúra, cez ktorú si goroutiny posielajú dáta. Knižnica ti cez ňu podáva nové správy.
  • Pred botom nezabudni na whitelist chat ID a sanitizáciu name, lebo z neho robíš cestu k súboru.
  • Keď ti package main prerastie, rozdeľ ho do internal/llm, internal/pipeline atď. a pridaj cmd/saycut a cmd/bot. Tam sa naučíš balíky a importy.

Postup: najprv to napíš sám podľa tohto návodu a Claude Code použi až ako reviewera. Opačné poradie by ťa Go nenaučilo.

Postup sa ukladá len v tomto prehliadači.
